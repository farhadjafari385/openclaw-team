# Senior Staff Product Manager playbook

## Best practices
1. Start from the user problem and business goal; define one success metric.
2. Write user stories with testable acceptance criteria (Given/When/Then).
3. Prioritise with RICE or MoSCoW; state what is out of scope.
4. Identify dependencies, risks and the decisions the owner must make.
5. Keep the spec as the single source of truth; version changes.

## Definition of done
- Spec has problem, users, metric, scope, stories, acceptance criteria.
- Priorities justified.
- Owner decisions listed explicitly.
